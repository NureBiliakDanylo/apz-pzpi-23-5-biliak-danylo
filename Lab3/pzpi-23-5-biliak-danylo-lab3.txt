2 ЗАВДАННЯ
На цій лабораторній роботі потрібно розробити front-end частину програмної системи. Ця частина системи повинна підтримувати роботу клієнтів у веб-режимі та забезпечувати адміністрування системи, тобто мати окремий інтерфейс для звичайних користувачів і окремий — для адміністраторів (відповідно до ролей користувачів вашої системи). Користувацький інтерфейс та інтерфейс адміністрування повинні підтримувати інтернаціоналізацію та локалізацію, а саме, забезпечувати: підтримку української на англійської мов сайту, формат дати та часу відповідний регіону, порядок сортування текстових значень, різні напрями введення тексту тощо. Адміністрування системи повинно забезпечувати: управління користувачами системи, управління даними системи, створення резервних копій налаштувань та даних, експорт та імпорт даних та налаштувань. Вимоги до оформлення Звіт повинен містити: - опис прийнятих інженерних рішень; - опис взаємодії компонентів web-застосунку одне з одним та з іншими елементами системи; - UML діаграму прецедентів (Use Case Diagram); - UML діаграму компонент (Component Diagram); - Дві діаграми, на вибір, із вказаних: - UML діаграму пакетів (Package Diagram); - UML діаграму взаємодії (Interaction Overview Diagram); - UML діаграму діяльності (Activity Diagram); - UML діаграму станів (State Diagram). Код web-застосунку необхідно завантажити на GitHub перез захистом роботи.

3 ОПИС ВИКОНАНОЇ РОБОТИ
1. Мета
Метою роботи було розробити веб-застосунок, який є частиною системи інтернету речей (IoT) та взаємодіє з центральним сервером для отримання та відображення даних з сенсорів, а також прогнозів.
2. Опис прийнятих інженерних рішень
Для розробки фронтенд-частини системи було обрано сучасний стек технологій, що забезпечує швидкість розробки, типізацію та ефективність:
- React 19: Основна бібліотека для побудови інтерфейсу користувача за допомогою компонентного підходу.
- TypeScript: Використання статичної типізації для зменшення кількості помилок під час розробки та полегшення підтримки коду.
- Vite: Інструмент для швидкого збирання та розробки проекту.
- Vanilla CSS + CSS Variables: Стилізація виконана без важких фреймворків, використовуючи сучасні змінні CSS для реалізації темної/світлої тем та динамічної зміни кольорів.
- React Router 7: Організація навігації між сторінками застосунку (SPA).
- i18next: Потужна бібліотека для реалізації багатомовності (Localization/Internationalization).
- Context API: Використовується для глобального управління станом авторизації ("AuthContext") та налаштувань одиниць вимірювання температури ("UnitContext").
 3. Опис взаємодії компонентів
Застосунок побудований за архітектурою SPA (Single Page Application). Основні принципи взаємодії:
- Ієрархія компонентів: "App.tsx" є кореневим компонентом, який обгортає систему в Провайдери контексту (Auth, Unit) та налаштовує роутинг.
- API шар: Всі запити до бекенду винесені в окремий модуль "api.ts", що використовує бібліотеку Axios. Це забезпечує централізовану обробку URL та заголовків.
- Захищені маршрути: Компонент "ProtectedRoute" перевіряє наявність токена авторизації перед доступом до адмін-панелі.
- Реактивність: При зміні одиниць температури в "UnitContext", всі компоненти (Dashboard, SensorDetail), що використовують функцію "convertTemp", автоматично оновлюють відображувані значення без перезавантаження сторінки.


 4. Інтернаціоналізація та локалізація
Система повністю підтримує дві локалі: Українську (UK) та Англійську (EN).
- Текстові ресурси: Зберігаються у JSON файлах ("src/locales/").
- Формати: Дати та час форматуються відповідно до обраної мови через метод "toLocaleString()".
- Одиниці вимірювання: Реалізовано вибір між Цельсієм, Фаренгейтом та Кельвіном, що є частиною локалізації під регіональні стандарти користувача.
- Сортування: Використовується стандартний механізм сортування рядків JavaScript, який враховує особливості алфавітів.
 5. Адміністрування системи
Інтерфейс адміністратора забезпечує:
- Управління користувачами: Реєстрація адміністратора при першому запуску системи.
- Управління даними: Перегляд повного списку сенсорів, включаючи їхні секретні API-ключі та дані, що вони відправляють на сервер.
- Видалення даних: Можливість повного видалення сенсора та всіх пов'язаних з ним показників.
- Експорт даних: Реалізовано функцію завантаження повного дампу бази даних у форматі SQL для резервного копіювання.
